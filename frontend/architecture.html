Key Capabilities
Streaming
Sub-second latency with Apache Flink or minute-level with AWS Glue Streaming. Iceberg sink in append or upsert mode. Exactly-once semantics via checkpointing. Merge-on-read for streaming; copy-on-write for batch reads.
Iceberg v2
ACID transactions · Schema evolution · Time travel · Partition evolution · Compaction
OPTIMIZE table REWRITE DATA USING BIN_PACK; (Athena small file compaction)
SELECT * FROM table FOR SYSTEM_TIME AS OF TIMESTAMP '2026-01-01'; (time travel)
Nessie
Git-like data branching: dev → staging → prod. Commit, merge, rollback data changes like code. REST API. Self-hostable on ECS or Dremio Arctic as managed service.
Governance
Column/row-level security via AWS Lake Formation. Amazon DataZone for business catalog and data discovery. Schema evolution without rewriting data — add, rename, or drop columns in place.

Why Option D First?
Speed
Demonstrable in one day. No cluster provisioning, no IAM setup, no DevOps overhead. Raw data to live dashboard in hours. This is the PoC that convinces stakeholders to invest in Option A.
Cost
~€5/month (S3 storage only). Zero compute at runtime — data is pre-aggregated and served as static JSON. The cheapest possible production artifact that proves the architecture concept.
Real Iceberg
Uses the real Apache Iceberg v2 format — the same table format as Option A. Time travel, ACID semantics, schema evolution. The PoC uses the same data foundations as the production path.
Limitations
Not production-grade: DuckDB is single-node (limited above ~100 GB). SQLite catalog doesn't scale. No streaming. No governance. No multi-user query engine. These gaps are exactly what Option A closes.
